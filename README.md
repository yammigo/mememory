## 🧠 核心功能详解

### ① 主动记忆提取

每轮对话结束后，系统自动分析对话内容，通过 LLM 提取值得记住的信息：

| 应该提取                     | 不应该提取               |
| ---------------------------- | ------------------------ |
| 用户偏好（喜欢/讨厌/习惯）   | 通用知识（天气、新闻）   |
| 身份信息（职业/所在地/年龄） | 闲聊寒暄（你好、谢谢）   |
| 重要事件或经历               | 临时信息（今天几点开会） |
| 用户明确要求记住的内容       | 助手的回答内容           |
| 有情感色彩的表达             | -                        |

提取流程：

```
用户消息 → Agent.chat() → LLM 回复 → extractMemories()
                                        │
                                        ▼
                              发送上下文给提取 LLM
                                        │
                                        ▼
                              解析 JSON 事实列表
                                        │
                               ┌───────┴───────┐
                               ▼               ▼
                         置信度匹配        新建记忆
                      (冲突检测+强化)    (自动分层)
                               │               │
                               └───────┬───────┘
                                       ▼
                                 保存对话快照
```

### ② Embedding 语义检索

**两阶段混合检索**，平衡召回率和精度：

```
用户查询: "我喜欢什么编程语言"
          │
          ▼
┌─────────────────────────────────────┐
│ 阶段一：BM25 + 规则评分（同步）       │
│ · 分词 TF-IDF 余弦相似度 ×30         │
│ · 标签精确匹配 +12                   │
│ · 层级加成 (core 12 / long 6 / ...) │
│ · 时间新鲜度 (7天内 +4 / 3天内 +5)    │
│ → 召回 Top 30 候选                  │
└─────────────────────────────────────┘
          │
          ▼
┌─────────────────────────────────────┐
│ 阶段二：Embedding 精排（异步）       │
│ · 查询向量 × 候选向量 → 余弦相似度    │
│ · 加权合并：BM25分数 + cos×45         │
│ → 返回 Top K 结果                   │
└─────────────────────────────────────┘
```

支持本地模型（`model/` 目录）和 CDN 远程加载两种模式，默认使用 `Xenova/all-MiniLM-L6-v2`（384 维）。

### ③ 置信度动态累积

```
新记忆创建: confidence = 0.3 (主动提取) 或 0.6 (手动/AI对话)
     │
     ▼
后续对话中再次提及相同信息
     │
     ├─ 无冲突 → confidence += 0.08 (上限 0.99)
     │
     └─ 有冲突 (否定词方向反转) → 旧记忆 confidence -= 0.2
                                 新记忆创建 (source: "冲突更新")
                                 旧记忆 tag += "可能过时"
```

冲突检测通过分析否定词（不、没、不再、讨厌、反感...）判断新旧信息方向是否一致。

### ④ 长内容切分 + 递归摘要

```
原文 (2000 字)
     │
     ▼ split()
┌─────────┬─────────┬─────────┐
│ Chunk 1 │ Chunk 2 │ Chunk 3 │   (500字/块, 80字重叠)
│ 500字   │ 500字   │ 500字   │
└────┬────┘────┬────┘────┬────┘
     │         │         │
     ▼         ▼         ▼
  LLM 摘要  LLM 摘要  LLM 摘要   (1-2句话)
     │         │         │
     └────┬────┴────┬────┘
          ▼         ▼
        合并 → 再次分割 → 再次摘要   (最多2层递归)
```

### ⑤ Token 预算智能选择

上下文窗口分配策略：

```
┌────────────────────────────────────────────┐
│            上下文窗口 (128K)                 │
├──────────┬────────────┬────────────────────┤
│ System   │  Memory    │  History           │
│ Prompt   │  Injection │  Messages          │
│ ~500 tok │  ~剩余预算  │  ~55% 总预算        │
└──────────┴────────────┴────────────────────┘

记忆注入优先级:
1. 核心记忆 → 全部注入 (不占预算，保底)
2. 搜索结果 → 按评分排序，动态内容长度
   · 排名 1-3:  300 字/条
   · 排名 4-8:  200 字/条
   · 排名 9+:   100 字/条
3. 相似记忆 → 标记 [旧版]，较新版本优先展示
```

### ⑥ 有效重要度算法

记忆的真实价值通过 **双时间线模型** 动态计算，综合以下因素：

```
EffectiveImportance = BaseImportance
                    × StorageDecay      // 存储衰减: exp(-decay × days × 0.3)
                    × RecencyBoost      // 检索活跃: exp(-decay × idleDays × 0.7)
                    × FreqFactor        // 频率因子: min(1, 0.3 + log₂(1+N) × 0.15)
                    × TemporalWeight    // 分布权重: 0.7 + (recentRatio × 0.3)
                    × ConfidenceFactor  // 置信度: 0.5 + confidence × 0.5
```

- **存储衰减**：记忆越老衰减越快（长期记忆衰减率 0.02/天，短期 0.15/天）
- **检索活跃**：最近被访问的记忆有显著加成
- **频率因子**：高频访问比低频更有价值（对数增长，边际递减）
- **时间分布**：近期集中访问 > 均匀分布
- **置信度因子**：高置信度放大概率，低置信度缩小

## 🏛️ 分层记忆架构

```
                    ┌─────────┐
                    │  CORE   │  核心记忆，永不遗忘
                    │  No decay│  · 用户身份信息
                    │  ∞ cap  │  · 核心偏好/约定
                    └────┬────┘
                         │ 访问≥20次 + 重要≥0.7
                    ┌────┴────┐
                    │LONG_TERM│  长期记忆，缓慢衰减
                    │ decay   │  · 已验证的事实
                    │ 0.02/day│  · 多次提及的偏好
                    │ cap:500 │  t½ ≈ 35 天
                    └────┬────┘
                         │ 访问≥5次 + (重要≥0.5 或 强化≥3)
                    ┌────┴────┐
                    │  SHORT  │  短期记忆，默认层级
                    │ _TERM   │  · 新信息
                    │ decay   │  · 待确认内容
                    │ 0.15/day│  t½ ≈ 4.6 天
                    │ cap:100 │
                    └────┬────┘
                         │ 访问≥2次
                    ┌────┴────┐
                    │ WORKING │  工作记忆，临时上下文
                    │  No decay│  · 对话历史快照
                    │  cap:20  │  · 截断溢出保存
                    └─────────┘
```

**自动巩固机制**（每 60 秒执行一次）：

- 符合条件 → 晋升到更高层级（带 7 天冷却期）
- 有效重要度 < 0.1 → 降一级
- 容量超限 → 淘汰最弱的记忆为新晋升腾位

## 🔧 工具调用

AI 助手拥有 7 个 Function Calling 工具：

| 工具               | 触发场景                     | 示例                         |
| ------------------ | ---------------------------- | ---------------------------- |
| `search_memory`    | 回答涉及用户信息的问题前     | "你之前说喜欢什么颜色？"     |
| `create_memory`    | 用户说"记住"或提供重要新信息 | "帮我记住我的生日是5月20日"  |
| `update_memory`    | 发现记忆过时或需修正         | 用户改了偏好                 |
| `delete_memory`    | 用户要求删除或信息完全过时   | "忘掉我之前说的那个"         |
| `list_memories`    | 浏览记忆库                   | "列出所有关于编程的记忆"     |
| `get_current_time` | 需要时间上下文               | 时间戳相关操作               |
| `get_conversation` | 查看记忆的原始对话           | "这条记忆是哪个对话产生的？" |

## 🚀 快速开始
### 方式一：npx 直接运行（无需克隆仓库）

```bash
# 需要 Node.js ≥ 18
npx memory-agent
# → 自动启动本地服务并打开浏览器 http://127.0.0.1:8080

# 常用选项
npx memory-agent --port 3000          # 自定义端口
npx memory-agent --host 0.0.0.0       # 允许局域网访问
npx memory-agent --no-open            # 不自动打开浏览器
npx memory-agent --help               # 查看全部选项
```

> 💡 包内不含 Embedding 模型文件（约 350MB），首次使用语义检索时自动从 HuggingFace CDN 下载模型（浏览器缓存，仅需一次）；也可以设置 `--host` 后在局域网内多人使用。

#### 导入本地模型

npm 包默认不携带模型，如需使用本地模型，可执行：

```bash
# 通过 npx 使用
npx memory-agent model:import

# 或克隆源码后使用 npm script
npm run model:import
```

命令会弹出文件夹选择器，选择包含模型文件的文件夹后，自动复制到 `dist/model/` 目录。

也支持无界面指定路径：

```bash
npx memory-agent model:import --path /path/to/model-folder
# 或
node scripts/model-install.mjs --path /path/to/model-folder
```





### 首次使用配置

1. 在欢迎页填写 LLM API 信息：
   - OpenAI: `https://api.openai.com/v1` + `gpt-4o-mini`
   - DeepSeek: `https://api.deepseek.com/v1` + `deepseek-chat`
   - 或点击快速配置按钮自动填充

2. 等待 Embedding 模型加载完成（侧栏状态指示器变绿）

3. 开始对话！系统会自动提取记忆

## 📊 衰退分析

### 衰减曲线

Canvas 绘制的实时衰减曲线，显示：

- **青色曲线**：短期记忆衰减（半衰期 ~4.6 天）
- **黄色曲线**：长期记忆衰减（半衰期 ~35 天）
- **红色区域**：危险区（有效重要度 < 20%）
- **散点**：每条有衰减的记忆的实际位置

### 遗忘预测

基于当前衰减率预测未来时间点的记忆丢失数量：

- 1天后、3天后、7天后、14天后、30天后

### 层级健康

四个层级的健康度百分比：

- 🟢 绿色：健康率 ≥ 70%
- 🟡 黄色：40-69%

## 🧪 技术细节

### Token 估算

```
中文字符 × 0.7 + 英文字符 × 0.25 + 2 (padding)
```

适用范围：GPT 系列 tokenizer 的粗略估算，用于上下文预算分配。

### 双时间线模型

```
存储龄 = (now - createdAt) / 86400000         # 天数
检索龄 = (now - lastAccessed) / 86400000      # 天数
```

记忆的价值取决于两个时间维度：

1. **存储时间**：记忆有多老（影响基础衰减）
2. **检索间隔**：最近一次被访问是什么时候（影响活跃度加成）

### 容量淘汰策略

当层级达到容量上限时，按 `有效重要度` 升序排列，淘汰最弱的记忆：

- 如果可以降级 → 降到下一层
- 如果已是最低层 → 删除
